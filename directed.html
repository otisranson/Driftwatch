Driftwatch · directed information

The co-occurrence map shows which signals belong together, but mutual information is symmetric: it can't tell you whether nic-flapping leads to unreachable or the other way round. Directed information adds time to the picture. It measures how much a signal's past predicts another signal's next hour, beyond what that signal's own past already predicts. The result is arrows: chains of signals that point back towards where a problem started.

1 · From “together” to “before”

Each signal is now a time series per host: Xt = 1 if a ticket with that template fired on the host in hour t. Rather than one co-occurrence table, we ask how much a signal's history helps forecast another.

Directed information (Massey)
I(Xⁿ→Yⁿ) = Σᵢ I(Xⁱ ; Yᵢ | Yⁱ⁻¹)
Information that flows from the X sequence into the Y sequence, accumulated causally: at each step, only X up to now may be used, and Y's own past is already known. Unlike I(X;Y), I(X→Y) ≠ I(Y→X).
What this page estimates
DI(X→Y) ≈ I(X₍ₜ₋ₖ..ₜ₋₁₎ ; Yₜ | Y₍ₜ₋ₖ..ₜ₋₁₎)
The per-hour directed information rate with k hours of memory (equal to transfer entropy under that assumption). The same-hour Xt is left out on purpose: same-hour coupling is what MI already measures, and it has no direction.
Net flow
F(X,Y) = DI(X→Y) − DI(Y→X)
Which way the information mostly runs. Positive = X tends to come first. A big DI in both directions means a feedback loop, or a shared cause that hits both at different moments.

Values are tiny per host-hour, so they're shown in millibits (1 mbit = 0.001 bit). Each estimate is bias-corrected and tested (G-test, corrected for testing every ordered pair), so a hover can say both how often the pattern was seen and whether it's distinguishable from noise.

2 · The map

Simulated fleet: every host produces an hourly series per signal. Hidden causes set off signals in a fixed order with delays (listed in section 3), on top of independent background noise. The estimator never sees the causes or the delays; it works only from the ticket timelines.

3 · Experiment

Each hidden cause fires a chain of signals with delays (+2h = two hours after onset, +1–2h = jittered). Toggle causes, change the memory k, or shrink the fleet to see how much data it takes to resolve a direction.

4 · Reading it

  • Arrows point downstream. nic-flapping → unreachable → … means the first tends to precede the second. Follow arrows backwards to the most upstream signal; that's usually the ticket to work first.
  • Strong MI, no arrow = same-hour coupling. Rack power loss sets off psu-lost and unreachable in the same hour. Switch to “Same-hour MI” and they're tightly linked; under directed information there's no arrow between them, because hourly data can't say which came first. Finer time bins would help.
  • Directed is not causal. Press Add a hidden confounder: a nightly batch job (not itself a signal) causes high CPU, and two hours later failed backups. The map then draws high-cpu → backup-failed even though neither causes the other. Directed information measures predictive precedence. A hidden common cause with different delays produces arrows too.
  • Memory must cover the delay. With k = 1, only one-hour delays are visible, so two- and three-hour links fade or vanish. Too much memory costs data: cells grow as 22k+1, and weak links slip below the noise floor on small fleets.
  • Rare is not the same as weak. The hover tells you how often a pattern was actually seen. A link seen only a dozen times can carry a big DI value and still be noise, which is why each edge also gets a significance tag.
  • Time-reversal check. Reverse time and every chain should flip direction, while same-hour links stay put. An arrow that doesn't flip is a warning sign.
