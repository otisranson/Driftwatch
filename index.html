Driftwatch

Two numbers from information theory — Shannon entropy and KL divergence — turn raw telemetry into a signal that says "the shape of your traffic just changed." Everything below is interactive, runs offline, and lives in one HTML file. Next page: the signal co-occurrence map → The headline use case is catching a fleet's ticket subject lines when they start to change (sections 2–4); sections 5–7 are the underlying mechanics on other kinds of telemetry.

1 · The two ideas

Shannon entropy — "how spread out is it?"

H(P) = − Σ pᵢ · log₂ pᵢ [bits] 0 ≤ H ≤ log₂ N

Low entropy: traffic concentrated on a few values (one hot endpoint, one noisy IP, one error code). High entropy: spread evenly. It tells you how much variety there is, not whether the variety is normal.

KL divergence — "how different from normal?"

D(P‖Q) = Σ pᵢ · log₂(pᵢ / qᵢ) [bits] ≥ 0, = 0 only when P = Q

P is what you observe now, Q is the baseline. It is the extra bits wasted when you encode live traffic with a model of "normal". It is asymmetric — D(P‖Q) ≠ D(Q‖P) — and blows up when P puts mass where Q says "never".

Why infra teams care
Metrics like "requests/sec" miss composition changes. A credential-stuffing run can leave total RPS flat while the endpoint mix is wildly off.
What you need
A categorical field (endpoint, status, source ASN, error class, node ID), a baseline histogram, and a sliding window of recent counts.
Cost
O(N) per window, N = number of categories. A handful of counters per field — cheap enough to run in a sidecar or a log pipeline stage.

A fleet of thousands of servers files thousands of tickets a day. 3 · Live fleet ticket simulator

A simulated fleet of 40 racks files about 3,000 tickets a day across 18 subject templates, with a daily rhythm. The detectors learned a baseline from 14 healthy days and calibrated thresholds on the next 7. Each tick advances simulated hours; the detectors look at the trailing 24 hours. Inject an incident and compare which detector notices, and how fast. Counts get +0.5 smoothing, so a template never seen in the baseline gets a small non-zero q instead of an infinite divergence.

7 · Load balancer evenness

Six backends. Set the share of traffic each receives. For a uniform target U there is a neat identity: D(P‖U) = log₂N − H(P), so entropy and KL are two views of the same balance score.

Practical notes

  • Smooth your counts. Use add-α (here α = 0.5) so empty buckets don't yield ∞.
  • Window size is a trade-off. Tiny windows have biased entropy (it under-estimates with few samples) and noisy KL; huge windows react slowly.
  • Baselines are seasonal. Keep per-hour-of-week baselines, or the daily cycle will look like drift.
  • Entropy alone is blind to which values. Swap which endpoint is hot and H stays put; KL does not. Use H for "concentration", KL for "difference", and the per-bucket terms for "who".
  • Cardinality. For high-cardinality fields (IPs, user IDs), hash into a fixed number of buckets or keep the top-K plus an "other" bin.
  • Threshold from data. Replay history, record the KL distribution on healthy windows, and set the alert at a high percentile of it.
